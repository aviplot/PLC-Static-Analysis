# M1 — CODESYS ST grammar, AST builder, TwinCAT unwrapping

Status: **approved 2026-10-18 ("ok, do m1")**. Grammar notes: `docs/grammar/codesys.md`.

## Goal
Parse CODESYS/TwinCAT Structured Text — IEC 61131-3 3rd edition ST including OOP — into our own AST with exact
spans, never failing on bad input. Validate against the harvested corpus, not only hand-written tests.

## Deliverables
| Module | Content |
|---|---|
| `plc-grammar` | `StLexer.g4` / `StParser.g4` (IEC core, imported) + `CodesysStLexer.g4` / `CodesysStParser.g4` (dialect root grammars). Switches to the `plca.antlr` convention. |
| `plc-ast` | Records + sealed interfaces: `SourceUnit`, `Pou` (PROGRAM/FUNCTION/FUNCTION_BLOCK/CLASS/INTERFACE/METHOD/PROPERTY/ACTION), `VarBlock`/`VarDecl`, `TypeDecl` (STRUCT/UNION/ENUM/ALIAS/SUBRANGE), `TypeRef`, statements, expressions, `Pragma`, `Comment`; `AstPrinter` for goldens. No ANTLR dependency. |
| `frontend-st` | `Utf16CharStream`; `StParserDriver` (two-stage SLL→LL, per-thread lexer/parser reuse); `StErrorStrategy` (sync-token recovery); `AstBuilder` (parse tree → AST, tolerant of error nodes); `TwinCatReader` (Woodstox StAX with char offsets → `XmlText` fragments); `StFrontend` facade (`.st` / `.TcPOU` / `.TcDUT` / `.TcGVL` / `.TcIO`). |
| tests | Lexer + AST golden tests per grammar feature (`src/test/resources/golden/`), error-recovery tests, TwinCAT span tests, Jazzer `@FuzzTest` with seed corpus (regression mode in `build`), corpus check task. |

## Key decisions
1. **Core vs dialect split.** IEC ed.3 constructs live in `StLexer`/`StParser`; CODESYS-only constructs (PROPERTY,
   `REFERENCE TO`, `POINTER TO`, `__NEW`/`__TRY`, `S=`/`R=`/`REF=`/`?=`, `UNION`, `VAR_INST`, `JMP`, `AND_THEN`/`OR_ELSE`)
   in `CodesysSt*`, which `import` the core. SCL (M4) will import the same core.
2. **Few reserved words.** Keywords the corpus uses as identifiers (e.g. `CLASS`, `STEP`, `TASK`, `ON`, `REF`, `S`, `R`)
   are *soft*: the lexer emits them as tokens and `identifier` accepts them. `S=`/`R=`/`REF=` are `identifier '='`
   with a text predicate, so `IF S=1` still parses as a comparison.
3. **Hidden channels**: `COMMENTS` (2) for `(* *)` (nested), `/* */`, `//`; `PRAGMAS` (3) for `{…}`. The builder attaches
   pragmas to the declaration that follows them, and keeps every comment span on the `SourceUnit` for suppressions.
4. **UTF-16 offsets.** ANTLR's `CodePointCharStream` indexes code points; we use our own `Utf16CharStream`, so token
   offsets equal `Span` offsets even when comments contain emoji or CJK.
5. **Entry rules**: `compilationUnit` (full text files), `declarationPart` (TwinCAT `<Declaration>`: header + var
   blocks without `END_…`), `statementList` (TwinCAT `<ST>`, bare action/snippet files). `StFrontend` picks the entry rule.
6. **Two-stage parsing**: SLL + `BailErrorStrategy`; on failure, rewind and re-parse with LL + `StErrorStrategy`.
   Fallback counts are exposed as metrics.
7. **Recovery**: single-token insertion/deletion first (ANTLR default), then consume up to a sync set (`;`, `END_*`,
   `END_VAR`, …). The builder turns error regions into `InvalidStatement`/`InvalidExpression` nodes with spans.
   Unterminated comments/strings, stray characters and graphical TwinCAT bodies (NWL/CFC/SFC/FBD) become diagnostics.
   `StackOverflowError` on pathological nesting is caught and reported (`PLC-INT-001`).
8. **XML offsets**: Woodstox `XMLStreamReader2.getLocationInfo()` character offsets on a `Reader` over the decoded
   file text locate `<Declaration>`/`<ST>` content; `XmlText` (M0) decodes it with an exact source map.

## Corpus check (`./gradlew :frontend-st:corpusCheck`, moved to `:plc-devtools:corpusCheck` in M2, run by `scripts/ci.sh` when `corpus/external` exists)
- Parses every Codesys/TwinCAT file listed in `corpus/MANIFEST.csv`, in parallel.
- Reports: files/lines per second, % of files with no syntax error, **per-file and per-repo-weighted** (one repo
  holds 45% of `.st` files), SLL-fallback rate, top error messages with examples.
- Fails if the SLL-fallback rate among *error-free* files exceeds 2%, or if the error-free rate drops below the
  committed baseline (`frontend-st/corpus-baseline.properties`).
- Iterate on the grammar until the repo-weighted error-free rate for TwinCAT is ≥ 97% and the remaining failures are
  explained (other dialects in `.st`, generated garbage, unsupported vendor extensions).

## Fuzzing
Jazzer `@FuzzTest` on `StFrontend` for `.st` text and for TwinCAT XML. Invariants: no exception escapes, every
diagnostic span resolves inside the file. Regression mode runs in `build`; `JAZZER_FUZZ=1 ./gradlew :frontend-st:test
--tests '*Fuzz*'` fuzzes. Every crash found becomes a regression test.

## Out of scope
Semantic checks (M2), SCL (M4), graphical languages (M5/M6), conditional-compilation evaluation (`{IF defined}`
— both branches are parsed; noted for M2), JMH (M2).

## As built (2026-10-18)
- Corpus check, 92.9k files / 17.9M lines in ~32 s on 8 threads (~550k lines/s, single run, cold JVM):

  | format | error-free (files) | error-free (repo-weighted) |
  |---|---|---|
  | TcPOU | 98.93% | 98.70% |
  | TcDUT | 99.62% | 99.03% |
  | TcGVL | 99.57% | 99.66% |
  | TcIO | 99.86% | 99.84% |
  | `.st` (mixed vendors/tools) | 86.92% | 74.14% |

  Clean SLL fallbacks: 26 of 292k texts (0.009%; gate 2%). The baseline is in `frontend-st/corpus-baseline.properties`.
  The remaining failures are classified in `docs/grammar/codesys.md` §8.
- Constructs added because the corpus needed them are listed in `docs/grammar/codesys.md` §7.
- Fuzzing: ~1.6M Jazzer executions (`.st` and TwinCAT targets, with a keyword dictionary), no escapes, no invalid
  spans. Seeds: `src/test/resources/dev/plca/frontend/st/StFrontendFuzzTestInputs/`.
- Recovery: deleting a `;`/`END_*` is never used as a repair (it merged the next statement into the broken one); a
  stray `§` or `@` is a diagnostic on its own channel and does not disturb parsing.
- **Risk for M4**: ANTLR generates separate context classes per root grammar, so `AstBuilder` is written against
  `CodesysStParser`. SCL will need either its own builder or a thin adapter layer. Decide in the M4 plan.
