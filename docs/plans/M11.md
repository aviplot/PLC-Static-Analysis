# M11 — The languages the corpus has that we still skip

Status: **approved 2026-10-22**, decisions 1–4 as recommended (owner: "do it … do your best", no further questions).

## Goal
After M10 all four languages of CLAUDE.md go through one model, but several bodies in the corpus are still skipped
with an "unparsed" diagnostic (`PLC-XML-102`, `PLC-L5X-002`, TwinCAT graphical bodies since M1, `.L5K` listed as
skipped since M5). These were deferred on purpose in M1, M5 and M6. M11 reads them into the same `plc-ast`, so that
the semantic model, the rules, the drawings and the LSP see that code too.

## Design
Everything graphical goes through the IR we already have: `Network` (LD/FBD graph, lowered to statements by
`NetworkLowering`) and `Sfc` (lowered by `kit/SfcLowering`). No new IR, no rule changes; rules see new statements.

**Prerequisite refactor**: `NetworkBuilder` / `NetworkLowering` move from `frontend-plcopen` to `frontend-st/kit`
(next to `SfcLowering`), because `frontend-st` (TwinCAT) and `frontend-l5x` both need them and both
`frontend-plcopen` and `frontend-l5x` already depend on `frontend-st`. Pure move; existing golden files must not change.

### 1. TwinCAT NWL (LD and FBD)
- A StAX reader for CODESYS's `XmlArchive` object form (`<o t=…>`, `<v n=…>`, `<l2 n=… cet=…>`, `<n/>`), shared by
  NWL, CFC and SFC: a small generic object tree (`ArchiveObject`) with spans, then per-language translators. It is
  never a DOM of the whole file: one `<Implementation>` at a time.
- A network is a **box tree**: `BoxTreeAssign` (outputs ← `RValue`), `BoxTreeBox` (`BoxType`, `Instance`,
  `InputItems`, `InputParam`/`OutputParam` names, `CallType`, `EN`/`ENO`), `BoxTreeOperand`, `BoxTreeParallel`
  (LD parallel branch = OR), `BoxTreeDemux`, `BoxTreeTerminator`, plus `Label`, `OutCommented`, `Comment`, and
  `STSnippet` (49: ST inside a network, parsed with the ST parser).
- Translation to `Network` elements: each box → `BLOCK`, each operand → `IN_VARIABLE`/`OUT_VARIABLE` (in Ld view,
  `CONTACT`/`COIL`), parallel → OR join. No coordinates are stored, so drawings use `NetworkSvg.layout` (already used
  for producers without coordinates).
- **Open format questions** (`TODO(verify-format)`, written up in `docs/grammar/codesys.md` before code): the meaning
  of the `Flags` bits (negation, set/reset coil, rising/falling edge), `BoxTreeDemux`, jump/return networks. I infer
  them from the corpus first; to confirm, a handful of small POUs exported from a free TwinCAT XAE / CODESYS
  install would settle them (decision 4).

### 2. CFC (TwinCAT and PLCopen addData)
- Same `XmlArchive` reader. `CFCBoxElement`, `CFCInputElement`, `CFCOutputElement`, `CFCConnection`, pins,
  `CFCJumpElement`/`CFCLabelElement`, `CFCComposerElement`, `CFCCommentElement` → `Network` (FBD) with real
  coordinates (`CFCPoint`).
- CFC has an explicit execution order per element; it maps to `Element.order`, which `NetworkLowering` already
  honours for CODESYS FBD.
- The PLCopen CFC addData reuses the same translator (today only its standard FBD part is read).

### 3. TwinCAT SFC
- `SFCStep`, `SFCTransition`, `SFCBranch` (alternative/parallel), `SFCJump`, `SFCSegment` → `Sfc` IR, lowered by
  `SfcLowering`. Step actions, entry/exit actions and transition bodies are the POU's `<Action>`/`<Transition>`
  children, which are already read (ST) or read after §1 (NWL).
- `SFCMacro` (6): diagnostic, as for PLCopen macro steps (`PLC-XML-105`).
- The SFC drawing (M10 `SfcSvg`) then works for TwinCAT charts too.

### 4. Rockwell FBD routines (L5X)
- `FBDContent` → one `Network` (FBD) per `Sheet`: `IRef`/`ORef` → variables, `Block`/`Function`/`AddOnInstruction`
  → blocks (instruction parameters from `InstructionSet` / the AOI definition), `Wire` → connections, `ICon`/`OCon`
  → connector/continuation across sheets, `FeedbackWire` → feedback (the existing `PLC-XML-104` check), `TextBox`
  → comment.
- Execution order: Rockwell orders FBD by data flow, sheet by sheet; `NetworkLowering`'s topological order already
  does that. `TODO(verify-format)` for the order of independent elements and for `Attachment`.
- Drawings use the stored `X`/`Y`. `PLC-L5X-002` remains only for what is still not read.

### 5. Rockwell L5K
- A new pair of grammars `L5kLexer.g4` / `L5kParser.g4` for the **structure only**: blocks
  (`CONTROLLER … END_CONTROLLER`, `DATATYPE`, `ADD_ON_INSTRUCTION_DEFINITION`, `TAG`, `PROGRAM`, `ROUTINE`,
  `ST_ROUTINE`, `FBD_ROUTINE`, `SFC_ROUTINE`, `TASK`, `MODULE`) with their `(attr := value, …)` lists.
- Bodies reuse what exists: rung lines (`N: XIC(a)OTE(b);`) go to the existing **rung grammar**, `ST_ROUTINE` lines
  to the ST grammar, `FBD_ROUTINE`/`SFC_ROUTINE` to the §4 / M10 translators (their L5K form is the same elements
  as attributes; `TODO(verify-format)` until checked on the 17 repos).
- Output: the same intermediate model `L5xReader` produces, so tags, UDTs, AOIs, programs, tasks, the semantic
  model and drawings need no change. Spans map to the L5K text lines.
- `.L5K` files are read by the CLI, LSP and workbench like `.L5X`.

### 6. IL
- A small ANTLR grammar `IlLexer.g4` / `IlParser.g4` (shares the ST lexer's literals/identifiers via `import`;
  case-insensitive): labels, operators with modifiers (`N`, `C`, `(`), `CAL`, `JMP`, `RET`, function calls.
- Lowered to ST statements by simulating the current result (CR): `LD a / AND b / ST c` → `c := a AND b;`;
  conditional jumps → `IF … THEN` + the existing `JMP`/`LABEL` statements, so the JMP rule sees them. A temporary
  `$cr` only where the CR crosses a label (same idea as the M5 `$rcN` temporaries).
- Used for PLCopen `<IL>` bodies and IL implementations in CODESYS `.st` files (detected by IL markers after
  `END_VAR`; today they are a syntax error, which is a false diagnostic).

## Order, and what "done" means for each step
In order of corpus value: (0) move `NetworkLowering` → (1) NWL → (2) CFC → (3) TwinCAT SFC → (4) L5X FBD →
(5) L5K → (6) IL. Each step is its own set of commits and leaves `./gradlew build` green.

Per step, following "How to work in this repo":
- format notes in `docs/grammar/<dialect>.md` first (with every `TODO(verify-format)`), then tests, then code;
- golden files for the AST and the lowered statements; fixtures only from permissive (`fixture-ok`) repos, with
  attribution in `corpus/SOURCES.md`, otherwise hand-written;
- new grammars (L5K, IL) join the SLL-fallback CI check and get a Jazzer fuzz target; the `XmlArchive` reader gets a
  Jazzer target too;
- **corpus run**: share of bodies read without a diagnostic (target ≥ 95 % repo-weighted for 1–4), lowering
  diagnostics, no crash, parse time added;
- **rule review**: findings on the newly visible code reviewed for false positives (as in M7), fixed in the
  lowering where the lowering is the cause;
- drawings checked in the workbench and the HTML report for each new graphical source.

## Decisions
1. **Scope**: all six (recommended), or stop after 1–4 (graphical only, about 80 % of the value).
2. **NWL in Ld view as `Network` (LD), not `Ladder`.** `Ladder` (series/parallel) is built around Rockwell
   instructions; `Network` already lowers and draws LD contacts/coils. Recommended: `Network`.
3. **IL**: include (recommended — small grammar, completes the five IEC languages, and removes the false syntax
   error on the `.st` IL files), or leave it out given 37 bodies.
4. **Format confirmation**: NWL/CFC/SFC are undocumented. I infer them from the corpus and mark every guess
   `TODO(verify-format)`. If you can export a few small POUs from a free TwinCAT XAE or CODESYS install (one LD
   network with negated contact, set/reset coil, edge; one CFC; one SFC), the guesses become tests. Recommended:
   proceed on the corpus, confirm when exports are available.

## Out of scope
- TwinCAT `StateChart` (7 bodies), the TwinCAT 2 `LADDER`/`FBD` forms (6): diagnostic stays.
- Siemens LAD/FBD/STL (no `.awl` or Openness XML in the corpus; P0 did not harvest them), `.ACD`.
- NWL networks in IL view (`ILActive` is never true in the corpus).
