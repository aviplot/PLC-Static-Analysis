# M4 — Siemens SCL as a dialect grammar on the shared ST core

Status: **done 2026-10-19; approved 2026-10-19** (builder: shared kit, option A; quoted names case-insensitive; classic STEP 7: cheap support for now, fuller support kept as a TODO). Grammar notes will go in `docs/grammar/siemens-scl.md` (written first, after
approval).

## Goal
Parse Siemens SCL source exports (`.scl`, `.db`, `.udt` from TIA Portal; classic STEP 7 SCL where it is cheap) into
the **same** `plc-ast`, with exact spans. Build the semantic model for it and run the M3 rules on it unchanged where
they make sense. Validate against the 11.5k Siemens files (2.9M lines, 393 repos) already in the corpus.

## Key decisions

### 1. Grammar: `SiemensSclLexer` / `SiemensSclParser` import the shared core
Same pattern as M1. The dialect grammars `import StLexer` / `import StParser` and override the extension-point
rules only. The SCL-specific parts:
- **Lexer**:
  - `QUOTED_IDENT : '"' ~["\r\n]* '"'`. It comes before the core's `WSTRING_LITERAL`, so `"…"` is a name in
    SCL. SCL writes WString literals as `WSTRING#'…'`.
  - Keywords: `ORGANIZATION_BLOCK`, `DATA_BLOCK`, `BEGIN`, `REGION`/`END_REGION`, `GOTO`, `CONST`/`END_CONST`,
    `LABEL`/`END_LABEL`, `VAR_STAT`, `KNOW_HOW_PROTECT`, `VERSION`/`AUTHOR`/`FAMILY`/`NAME`. All of these except
    the block keywords are **soft** (usable as names), the same policy as M1.
  - `TITLE = …` and `REGION <name>` take free text up to the end of the line. Each becomes **one** token
    (`TITLE_TEXT`, `REGION_START`), but only at the start of a line and only when the text is not followed by
    `:=`, `.`, `[` or `(`, so a variable called `region` still lexes as a name. The edge cases go in the grammar
    notes and get lexer tests.
  - `S5TIME_LITERAL`, plus `%DB1.DBX0.0` / `%DB1.DBW2` and the `%I/%Q/%M` forms in `DIRECT_ADDRESS`. Slice
    suffixes (`.%X3`, `.%B1`, `.%W0`, `.%D0`) are a `SLICE` token.
  - The `{ key := 'value'; … }` attributes stay on the `PRAGMAS` channel. The builder parses them as key/value
    pairs (not as free text) because `ExternalWritable` and `S7_Optimized_Access` matter for later rules.
- **Parser**:
  - The `identifier` override adds `QUOTED_IDENT`. The `designatorRoot` override adds `HASH identifier` (`#x`,
    `#"x y"`); the builder checks that no whitespace follows `#`.
  - `postfixOp` gets a slice operator.
  - Block rules: `organizationBlock`, `sclFunctionBlock` / `sclFunction` (`BEGIN` between the VAR sections and the
    body), `dataBlock` (`STRUCT … END_STRUCT;`, `"FB"` instance DB or `"UDT"` typed DB, then `BEGIN` with
    initial-value assignments), and the single-type `TYPE "x" VERSION : 0.1 STRUCT … END_STRUCT; END_TYPE`.
  - `blockAttribute*` for `TITLE`/`AUTHOR`/`FAMILY`/`NAME`/`VERSION`/`KNOW_HOW_PROTECT`/`RETAIN`/`NON_RETAIN`.
  - Statements: `regionStatement`, `gotoStatement` + labels, and `ELSE:` (accepted, kept as a token-level fact).
  - Declarations: `constSection`, `labelSection`, and the `AT` overlay in `varDeclaration`
    (`name AT otherVar : type`).
- **No predicate-heavy merged grammar.** Rule 3 says a dialect with many differences gets its own grammar file, and
  SCL has its own lexer vocabulary anyway (`"…"` changes meaning).

### 2. AST builder: share the code, not the parse tree types (**decision needed**)
ANTLR generates separate context classes for every root grammar (`CodesysStParser.IfStatementContext` ≠
`SiemensSclParser.IfStatementContext`), even for imported rules. The M1 `AstBuilder` (1,280 lines) is typed against
the CODESYS classes. Options:

| | Option | Cost | Risk |
|---|---|---|---|
| **A (recommended)** | **Shared builder kit + a thin SCL builder.** Move the language-neutral parts of `AstBuilder` into a reusable `frontend-st` package (`dev.plca.frontend.st.kit`): literal decoding, spans, comments/pragmas, invalid-node handling, operator tables, the generic two-stage driver (over any `Lexer`/`Parser` pair) and `StErrorStrategy` (with a sync-token set per dialect). `SclAstBuilder` handles the SCL contexts and duplicates only the per-rule glue for statements/expressions (~400 lines). A **conformance test** runs every core-ST golden input through both frontends and requires identical ASTs, so the duplicated glue cannot drift. | medium | duplicated glue (contained by the conformance test) |
| B | A grammar-agnostic builder that dispatches on rule *names* and token *symbolic names* (maps resolved once per parser). | lower code size | no compile-time checking; grammar refactors break at runtime |
| C | One combined parser grammar with dialect predicates. | — | goes against grammar rule 3; SCL needs its own lexer vocabulary anyway |

This is the classic "one front end per dialect, shared lowering library" design. In the ABAP analogy it is the
macro/statement-level differences handled per dialect with one shared expression lowering. Option B is the
universal-tree approach; it is cheaper but gives up the typed visitor.

### 3. AST additions (`plc-ast`, dialect-neutral names)
- `PouKind.ORGANIZATION_BLOCK`. FB maps to `FUNCTION_BLOCK` and FC to `FUNCTION` (a `Void` return is allowed).
- `Declaration.DataBlock(name, kind = GLOBAL | INSTANCE_OF(fb) | OF_TYPE(udt), varBlocks/struct, initAssignments,
  info, span)`.
- `BlockInfo(title, author, family, name, version, knowHowProtect, attributes)` on POUs, DBs and types. The
  attributes include `S7_Optimized_Access`.
- `Identifier.Form { PLAIN, QUOTED, LOCAL }`. The semantic model uses it for scoping (`#x` is local only, `"x"` is
  global only). The printer shows it so goldens catch mistakes.
- `Statement.Region(name, body)`. Regions are kept as a nested node because the M8 outline and M9 workbench use
  them. Rules see through them (`statementsDeep`).
- `Statement.Goto` reuses the CODESYS `Jump`/label nodes. `Expression.Slice(base, width, index)`.
  `VarDecl.overlay` holds the `AT` view target. Pragmas on a declaration may sit between the name and `:`.
- `DirectAddress` gains the DB area (`%DB1.DBX0.0`, classic `DB10.DBW2`) with parsed area, size, byte and bit.

### 4. Semantic model (`plc-semantic`)
- **Scoping, Siemens rules**:
  - `#x` binds only to the block's locals (incl. `VAR_TEMP`, `CONST`).
  - `"x"` binds to global DBs, blocks, UDTs and PLC tags.
  - Unprefixed names (classic SCL and TIA DB bodies) resolve local-first.
  - **PLC tag tables** are not part of `.scl` exports (TIA exports them as XML/XLSX). An unresolved `"Tag"`
    becomes an `ExternalTagSymbol`, counted separately in the resolution statistics like library names: never an
    error, never guessed.
- **DBs**:
  - A global DB is a GVL-like container accessed by `"DB".member`.
  - An instance DB (`DATA_BLOCK "M_DB" "FB_Motor"`) is a global FB instance in the instance graph.
    `"M_DB"(…)` is a call on it.
  - `"IEC_Timer_0_DB".TON(…)` is a call of the system FB on a global instance (`TODO(verify-format)` in the notes:
    18 corpus files show it, and I'll confirm the semantics against the TIA help).
- **Overlay `AT`**: writes and reads through a view count as accesses to the base variable, so double coil and
  read/write sets stay correct.
- **Task model**: each OB is an entry point. TIA `.scl` exports don't contain the OB number or its event class. The
  model records "OB, cycle unknown" and doesn't infer it from the name (`"Main"` is usually OB1, but that's a guess).
  Race rules (M7) will treat different OBs as possibly different priorities.
- **Builtins**: a Siemens table, driven by data: the top unresolved names in the corpus. It covers `TON_TIME` /
  `TOF_TIME` / `TP_TIME` / `TONR_TIME`, `IEC_TIMER` / `IEC_COUNTER`, typed counters, `R_TRIG` / `F_TRIG`,
  `MOVE_BLK` / `FILL_BLK` / `Serialize`, `T_CONV`, `CONCAT` / `LEN`, `LIMIT` / `MIN` / `MAX`, `RD_SYS_T`,
  `DTL` members, `ENO`, and the `VARIANT` / `DB_ANY` / `ANY` types. Names not in the table become library symbols.

### 5. Frontend `frontend-scl`
`SclFrontend`:
- `.scl` (one or more blocks), `.db`, `.udt`.
- Encoding: reuse the M1 decoding (UTF-8 with BOM). A corpus check counts files that only decode as Windows-1252
  (classic exports) before deciding whether to add a fallback.
- Entry rule: `compilationUnit`.
- `ProjectLoader` dispatches by extension and tags every unit with `Dialect.SIEMENS`.
- A directory of TIA exports has no project file, so one project = one directory tree (the same fallback as `.st`
  repos).

### 6. Rules
- The M3 rules declare `dialects`. All ten run on SIEMENS, with these adjustments (each with fixtures):
  - **Q001**: members of global DBs are not reported, since HMIs and other blocks access them. `ExternalAccessible`
    is not used to exempt variables.
  - **P002**: also reports `%DB…`, classic `DBn.DBWm` and slice-free absolute DB access.
  - **Q006**: the same rule, since SCL also allows writing an input.
- The corpus check samples 20 findings per rule on SIEMENS for a false-positive review, with the same ≤ 20% bar as
  M3.
- No new rules in M4.

## Tests
- Grammar notes first. Then lexer tests (quoted names, `#`, TITLE/REGION free text with the name-collision cases,
  slices, DB addresses, S5T#), then AST goldens per feature in `frontend-scl/src/test/resources/golden/`.
- Error recovery: sync set adds `END_REGION`, `END_DATA_BLOCK`, `END_ORGANIZATION_BLOCK`, `BEGIN`, `END_CONST`.
  Bad input never throws.
- Conformance test (decision 2): the shared core-ST inputs give identical ASTs in both frontends.
- Semantic goldens: a hand-written TIA-style project (OB1 → FB with an instance DB, multi-instance, global DB,
  UDT, FC, overlay, unresolved PLC tags).
- Rule fixtures: one SIEMENS `noncompliant.scl` / `compliant.scl` per rule where the SCL form differs.
- Jazzer: an `SclFrontend` fuzz target (parse + model + rules), seeded from the goldens.
- Fixtures are hand-written (owned by us). Corpus files are used only by the corpus check, following the licence
  policy.

## Corpus check and performance
- `:plc-devtools:corpusCheck` adds a Siemens group with its own baseline:
  - error-free rate (files and repo-weighted)
  - SLL-fallback rate (≤ 2% among error-free files)
  - name-resolution rate, with external tags shown separately
  - rule statistics
- **Target**: repo-weighted error-free ≥ **95%** for TIA-style files, with the remaining failures explained
  (classic-only syntax, AX, generated or broken files). Classic STEP 7 files are reported on their own.
- JMH: `SclParseBenchmark` (two-stage vs LL) on generated SCL. Throughput should be close to CODESYS ST.

## Out of scope
- **TIA Openness / SimaticML XML** exports (LAD/FBD/STL networks, PLC tag tables). Tag tables would be the
  natural follow-up, because they turn external tags into real symbols.
- **STL/AWL** (statement list) and LAD/FBD.
- **SIMATIC AX** (`NAMESPACE`/`CLASS` ST, 5 files). It is closer to IEC-OOP ST and would be a separate dialect later.
- Evaluating `{ … }` attributes beyond storing them. Know-how-protected blocks (encrypted bodies) only get a
  diagnostic.

## Decisions (2026-10-19)
1. Builder: **option A**, the shared builder kit plus a thin SCL builder, guarded by the conformance test.
2. Quoted names are **case-insensitive** (`"Motor_DB"` = `"motor_db"`). Still to be confirmed against the TIA help
   in the grammar notes.
3. Classic STEP 7 SCL: cheap support and a separate measurement for now.

## As built (2026-10-19)
- **Shared kit** (`dev.plca.frontend.st.kit`, decision 1): `CoreTokens` (core token types looked up by symbolic name
  per dialect vocabulary — a root grammar numbers its own rules first, so core token types differ between dialect
  lexers), `TwoStageParser`, `RecoveryStrategy`, `BuilderSupport`, `Frontend`/`Frontends`. `ProjectLoader` takes a
  `Frontends` set (no ST-only default). The CODESYS builder kept only its context glue; M1 goldens and the corpus check
  were unchanged by the extraction.
- **Grammar** `SiemensSclLexer`/`SiemensSclParser` on the shared core; `frontend-scl` with `SclAstBuilder` and
  `SclFrontend` (`.scl`, `.db` — only if it declares a `DATA_BLOCK`, so SQLite files and `Thumbs.db` are skipped —
  and `.udt`). AST additions: `Identifier.Form`, `PouKind.ORGANIZATION_BLOCK`, `DataBlock`, `BlockInfo`, `Region`,
  `Slice`, `VarDecl.overlay`, compound `AssignOp`s, positional `FieldInit`s. Notes: `docs/grammar/siemens-scl.md`.
- **Corrections during M4** (both in the notes):
  - SCL comments **nest**. The first reading of the corpus was wrong; a scan of all files showed nesting breaks
    nothing and 8 files need it.
  - Build: every `.g4` is now a non-source input of `generateGrammarSource`. Incremental generation had regenerated
    only a changed lexer and left its parser with stale token types.
- **Corpus** (11,453 Siemens files; per-format table in the grammar notes §10): repo-weighted error-free `.scl`
  93.6% (95.7% of files), `.db` 94.5%, `.udt` 98.2%; classic STEP 7 `.scl` 83.9%. **The 95% repo-weighted target for
  `.scl` and `.db` is not reached.** Every remaining failure I inspected is not TIA export syntax (LLM/template code,
  linter fixtures, other tools' output, STL in `.scl`); single-file repositories make up most of the gap. SLL
  fallbacks on error-free texts: 0.009% over the whole corpus (gate: 2%).
- **Semantic model**: scoping by name form (`#x` locals only, `"x"` globals only, unknown `"x"` = external PLC tag);
  DBs as one global variable each (own STRUCT/VAR layout, UDT, or FB = instance DB and instance-graph root); `Void`
  FCs without a result; implicit `EN`/`ENO`; overlays; inferred `CONST` types; every OB a task with unknown
  priority/interval; Siemens builtins chosen from the corpus' top unresolved names. Siemens names: **96.6%** resolved,
  library or external (repo-weighted; resolved 90.7%, library 5.2%, external tags 1.8%, unresolved 2.3%). The CODESYS
  rates rose slightly (TwinCAT 95.9% → 96.0%, `.st` 86.8% → 87.3%) from the shared builtin fixes.
- **Rules** on SIEMENS, with fixtures in `plc-rules/src/test/resources/<id>/siemens/`:
  - Q001: statics count as HMI-accessible unless `ExternalAccessible := 'False'`; data blocks never reported.
  - P001: OBs are cyclic bodies; startup OBs (TIA/STEP 7 default names and titles: Startup, Restart, Anlauf,
    OB100–102) are not compared, like first-scan blocks.
  - P002: also `%DB…`, classic `DB10.DBW2`, `P#` pointers, with SCL-specific advice.
  - FP review of 20 Siemens samples per rule (`rule-samples/Siemens/`): Q001 0/20, Q002 0/15, Q003 1/20 (deliberate
    infinity check), Q005 0/3, Q006 0/20, Q007 0/4, P001 3/20 before the startup-OB exemption (all three were startup
    OBs; Siemens P001 findings 273 → 230 with the exemption), P002 0/15, S001 0/10. Q004 had no Siemens findings. No
    rule failed on any project.
- **CLI**: `plca analyze` reads SCL; L5X/L5K are still listed as skipped.
- **JMH** (`./gradlew :plc-devtools:jmh -Pjmh.args="Parse"`, one thread): generated SCL (403 files, 28.2k lines)
  44.3 ms two-stage vs 52.2 ms LL-only (≈ 636k lines/s, two-stage ~15% faster); ST on its generated project 26.2 ms
  (≈ 710k lines/s). The generated SCL is checked to parse without errors or SLL fallbacks.
- **Fuzzing**: `SclFrontendFuzzTest` 588k runs in 5 min, `RulesFuzzTest.fuzzSclRules` (parse + model + all rules)
  483k runs in 5 min; no failures.
- **Follow-ups**: classic STEP 7 (TODO above); the CODESYS grammar has the two recovery weaknesses fixed for SCL
  (keyword deletion after a broken condition, lost POUs after a broken one) — fixing them moves the M1 baselines;
  timer method calls as instance writes (grammar notes §9); TIA tag tables (SimaticML XML) to turn external tags into
  symbols.
